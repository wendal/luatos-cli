# Air1601 / Air1602 / Air1603 / Air1604 / CCM4211

## 适用型号

- Air1601
- Air1602
- Air1603
- Air1604
- CCM4211

## 推荐命令

```bash
# 全量刷机
luatos-cli flash run --soc firmware.soc --port COM10

# 全量刷机并覆盖脚本区
luatos-cli flash run --soc firmware.soc --port COM10 --script lua/

# 刷机后继续抓启动日志
luatos-cli flash run --soc firmware.soc --port COM10 --tail-log-secs 30

# 仅刷脚本区
luatos-cli flash script --soc firmware.soc --port COM10 --script lua/

# 查看二进制日志（建议带 probe）
luatos-cli log view-binary --port COM10 --baud 6000000 --probe

# 闭环验证
luatos-cli flash test --soc firmware.soc --port COM10 --timeout 15 --keyword "LuatOS@"

# 闭环验证（带脚本覆盖 + 自定义关键字）
luatos-cli flash test --soc firmware.soc --port COM10 --script lua_case_a --timeout 30 --keyword "CASE_A_ONLY_20260530"

# 闭环验证（快速判失败关键字）
luatos-cli flash test --soc firmware.soc --port COM10 --timeout 30 --keyword "CASE_A_ONLY_20260530" --fail-keyword "assert" --fail-keyword "panic"
```

## 说明

- Air1602 / Air1603 / Air1604 与 Air1601、CCM4211 是**同一颗 die 的不同 PCBA**
  （SDK `platform_define.h`：`MODEL_AIR1603 = CHIP_68P_16M + PCBA_TYPE2`、
  `MODEL_AIR1604 = CHIP_88P_32M + PCBA_TYPE2`），刷机路径完全一致
- 四个型号共用同一份固件二进制：SDK 用 `Air160X` 编译一次，产物分别拷成各型号名的 `.soc`
- `.soc` 内的 `info.json` 里 `chip.type` 固定为 `"air1601"`（SDK `csdk.lua` 硬编码），
  所以 `flash` 系列命令不需要 `--chip`，直接吃 `--soc` 即可
- `--chip air1603` / `--chip air1604` 主要用于 `log`、`device boot` 等不读 `.soc` 的命令
- 日志协议为 SOC 二进制帧，建议使用 `log view-binary`；V1013+ 固件波特率 6 Mbps
- `flash run --script` 会在全量刷机时用所选目录覆盖 SOC 包内自带脚本
- `flash test` 在本型号上如果传入 `--script`，会在全量刷机时覆盖脚本分区，再抓日志做关键字判定
- `--fail-keyword` 未传时不会触发快速判 FAIL；传入后命中任意关键字会立即 FAIL，减少等待时间
- 固件分区默认按块 LZMA 压缩后下发；MD5 校验失败会自动改用明文重传一次，
  排查压缩相关问题时可设环境变量 `LUATOS_CCM_LZMA=0` 强制走明文路径
